设计文档：热点雷达 + 淘金列表 + 盘后触发 + AutoTrade 接入

版本：1.0    状态：已实现    日期：2026-05

1. 背景与目标

原有 Scanner（中线 1–6 个月）和 GoldDigger（价值挖掘）均不具备短线新闻敏感能力。 本子系统新增四个能力：

  1. NewsHeatRadar（热点雷达）：独立查询 24-48h 新闻，识别板块热度，提名短线股票（5 日视野）。
  2. DiscoveryList（淘金列表）：独立于用户自选股的自动维护列表，由三个扫描源写入，纯 TTL 失效。
  3. 盘后自动触发：CN/US 收盘后各自触发完整 Scanner + GoldDigger + HeatRadar 流水线，结果写入淘金列表。
  4. AutoTrade 接入：AutoTradeService 处理淘金列表活跃股，使用短线参数（仓位小、止损紧）。

2. 整体架构

盘后自动触发（Scheduler market-close-watcher）
      ├─ CN 收盘 15:05 CST → _run_post_close_scan(markets=["cn"])
      └─ US 收盘 16:05 ET  → _run_post_close_scan(markets=["us"])
                                  │
             ┌────────────────────┼─────────────────────┐
             ▼                    ▼                      ▼
       MarketScanner         GoldDigger           NewsHeatRadar
       (20-40 min)           (15-25 min)          (5-10 min)
             │                    │                      │
             └────────────────────┴──────────────────────┘
                                  │ 完成后回调
                                  ▼
                           DiscoveryService
                                  │ add_from_scanner / add_from_gold_digger
                                  │ add_from_heat_radar
                                  ▼
                           discovery_list (SQLite)
                           status: active | expired | rejected
                           TTL: scanner=14d, gold_digger=21d, heat_radar=5d

AutoTradeService (每 5 min 循环)
      ├─ WatchlistService().list_all()     → 自选股（中线参数）
      └─ DiscoveryService().get_auto_trade_stocks() → 淘金列表（短线参数）
                                  │
             SignalService.generate_signal(trade_context="discovery_short_term")
             ↓
             OrderService.place_order() + 仓位/止损覆盖

3. NewsHeatRadar 模块

3.1 文件路径

  • src/schemas/news_heat_radar.py — HeatConfig / HotSector / HotPick / HeatReport
  • src/services/news_heat_radar.py — 主服务类 + 单例 get_news_heat_radar()

3.2 Pipeline 步骤

步骤说明耗时估算
Step 18 条搜索查询并发（days=2），构建 news_digest（最大 10k 字符）5-15s
Step 2LLM 从 digest 识别 top-N HotSector，按 heat_score 排序10-20s
Step 3对 top-5 板块各自 LLM 提名 3 只股票 → HotPick25-60s（5×5-12s）
Step 4按 market 过滤 → 去重（保留最高 heat_score）→ top_n<1s
Step 5保存 JSON → 发通知 → DiscoveryService 写入<2s

3.3 SearchService Fallback

当 SearchService 不可用（未配置搜索 API Key）时，news_digest 设置为固定提示语，LLM 依赖训练知识生成结果，heat_score 普遍偏低（confidence ≤ 60），仍可产出 HeatReport。

3.4 搜索查询维度（8条，days=2）

"breaking stock market news sector catalyst today"
"government policy regulation announcement stock sector impact this week"
"earnings surprise guidance raised revenue beat sector stocks"
"A股热门概念板块题材资金流向 近两日"
"Federal Reserve economic data jobs report GDP market reaction sectors"
"sector rotation money flow hot sector rally momentum today"
"supply chain disruption trade announcement sector winners losers"
"technology breakthrough product launch semiconductor AI chip stocks news"

与 ThemeDetector 的 7 条宏观查询（days=7）完全独立，聚焦更短时间窗口。

3.5 LLM Prompt 语义

_HEAT_SECTOR_PROMPT — 板块识别

输入：news_digest（≤10k chars）+ 日期 + count
输出：JSON array of HotSector
关键约束：heat_score = 新闻频次 × 影响权重；只有1条低影响提及的板块不纳入；需指定 market_regions。

_HEAT_STOCK_PROMPT — 个股提名

输入：sector_name + catalyst_summary + keywords + markets + n
输出：JSON array of HotPick
关键约束：直接暴露（非外围关联）；5个交易日内可能波动；避免市值 <100M 的微盘股；A股用数字代码，US股用字母 ticker。

3.6 结果存储

结果文件：data/scanner_cache/heat_results/{run_id}.json
单例访问：get_news_heat_radar()

4. DiscoveryList 模块

4.1 数据模型

discovery_list (SQLite)
  id             INTEGER PRIMARY KEY AUTOINCREMENT
  ticker         VARCHAR(20) NOT NULL  -- 股票代码
  name           VARCHAR(100)          -- 股票名称
  market         VARCHAR(8)  NOT NULL  -- CN | US | HK（已标准化）
  sector         VARCHAR(100)          -- 行业
  source         VARCHAR(20) NOT NULL  -- scanner | gold_digger | heat_radar
  source_run_id  VARCHAR(64) NOT NULL  -- 关联的扫描 run_id / scan_id
  score          FLOAT                 -- 来源评分（heat_score / composite_score）
  confidence     INTEGER               -- LLM 置信度 0-100
  thesis         TEXT                  -- 简短投资论点
  themes         TEXT                  -- JSON list 主题关键词
  trade_horizon  VARCHAR(16)           -- short | medium
  added_at       DATETIME              -- 写入时间（UTC）
  expires_at     DATETIME              -- 过期时间（UTC）= added_at + TTL
  status         VARCHAR(16)           -- active | expired | rejected
  rejected_at    DATETIME
  allow_auto_trade BOOLEAN DEFAULT 1

UNIQUE (ticker, source, source_run_id)  -- 同一扫描结果幂等

4.2 TTL 设计

来源默认 TTL环境变量逻辑
heat_radar5 天DISCOVERY_HEAT_RADAR_TTL_DAYS短线催化剂，快速失效
scanner14 天DISCOVERY_SCANNER_TTL_DAYS每两周扫一次
gold_digger21 天DISCOVERY_GOLD_DIGGER_TTL_DAYS价值反转慢，给更长窗口

失效检查：DiscoveryService.list_active() 和 get_auto_trade_stocks() 调用前先 expire_stale()（懒失效）。

4.3 重复处理

  • 同一 ticker 来自同一 source 的同一 run_id：UNIQUE 约束幂等忽略（重启安全）。
  • 同一 ticker 来自不同 source：DB 存多行；get_auto_trade_stocks() 去重后统一以 trade_context="discovery_short_term" 处理。
  • 同一 ticker 同时在自选股和淘金列表：AutoTrade 以自选股为准（watchlist_codes 过滤），不重复处理。

4.4 market 字段标准化

_normalize_market()："A-share" → "CN"，"cn" → "CN"，"us" → "US"，兼容三个来源的不同命名习惯。

5. 盘后自动触发

5.1 机制

Scheduler._add_market_close_watcher() 注册一个 60s 轮询的后台任务（add_background_task）：

  • CN：检测 Asia/Shanghai 时区 15:05-15:10 窗口 + 工作日 + 当日未触发（_fired["cn"]）
  • US：检测 America/New_York 时区 16:05-16:10 窗口 + 工作日 + 当日未触发（_fired["us"]）
_fired 字典在进程内防止重复触发，进程重启后重置。如重启恰好落在触发窗口内会再次触发，但淘金列表的 UniqueConstraint 保证幂等。

5.2 main.py 注册

--schedule 模式下，若 POST_CLOSE_SCAN_ENABLED=true（默认），自动调用 _add_market_close_watcher；POST_CLOSE_SCAN_MARKETS 控制触发范围（us,cn / 只填 us / 只填 cn）。

5.3 _run_post_close_scan

启动 Scanner + GoldDigger + HeatRadar 三个后台线程（fire-and-forget），返回后立即完成。各扫描在自己线程中完成后回调 DiscoveryService 写入淘金列表。并发安全：SQLite WAL 模式 + DatabaseManager 写重试。

6. AutoTrade 接入

6.1 合并逻辑（auto_trade_service.py）

watchlist = WatchlistService().list_all()
_discovery = DiscoveryService().get_auto_trade_stocks()  # 懒失效后返回

watchlist_codes = {item['code'] for item in watchlist}
watchlist += [item for item in _discovery if item['code'] not in watchlist_codes]

已在自选股中的 ticker 不重复处理，以自选股参数为准。

6.2 短线参数覆盖

对 _from_discovery=True 的买单，在 generate_signal() 返回后、place_order() 之前覆盖：

参数默认值环境变量
最大仓位占比10.0%DISCOVERY_AUTO_TRADE_POSITION_PCT
止损百分比5.0%DISCOVERY_AUTO_TRADE_STOP_LOSS_PCT
止盈百分比15.0%DISCOVERY_AUTO_TRADE_TAKE_PROFIT_PCT

仓位计算：qty = floor(cash × pos_pct% / entry_price)，对齐到手数（CN=100股，US=1股）。

6.3 SignalService trade_context 参数

generate_signal(code, market, name, trade_context="discovery_short_term")

  • LLM prompt 末尾追加短线上下文说明（优先催化剂动量，止损 3-5%，止盈 10-15%）。
  • 最低置信度阈值降至 DISCOVERY_MIN_SIGNAL_CONFIDENCE（默认 0.55，低于自选股的 0.65）。

9. 边界条件与风险

场景处理方式
SearchService 不可用news_digest 为空，LLM fallback prompt，报告仍产出但 confidence 低
盘后扫描耗时超 1 小时各服务后台线程独立，DiscoveryList 在各自完成后写入，AutoTrade 线程不受影响
进程重启落在触发窗口内_fired 重置→重新触发；UniqueConstraint 幂等保护
同一 ticker 被多源收录DB 多行，get_auto_trade_stocks() 按 score 去重，trade_context 统一为 short_term
market 字段不一致（"A-share" vs "CN"）_normalize_market() 统一到 CN/US
DiscoveryService 写入失败try/except + logger.warning，不影响主扫描流程通知发送

11. 回滚方式

  • 热点雷达：设置 HEAT_RADAR_ENABLED=false 禁用，CLI 不触发，盘后不触发，不影响其他模块。
  • 淘金列表自动交易：设置 DISCOVERY_AUTO_TRADE_ENABLED=false，AutoTrade 恢复只处理自选股。
  • 盘后触发：设置 POST_CLOSE_SCAN_ENABLED=false，market-close-watcher 不注册。
  • DB 表：discovery_list 是独立新表，删除后不影响任何现有功能。
  • 代码层面：所有集成点（Scanner/GoldDigger 钩子、AutoTrade 合并）均在 try/except 内，失败只 logger.warning，不影响主流程。
