1. Overview

This design introduces two core capabilities to the stock analysis system:

  • Persistent Memory: File-based cross-session storage for watchlists, preferences, and alert rules
  • Research Goal: Multi-session analysis lifecycle with state tracking and evidence accumulation

2. Persistent Memory System

2.1 Storage Layout

~/.daily-stock-analysis/
├── memory/
│   ├── INDEX.md              # Auto-generated memory index
│   ├── watchlist.md          # Stock watchlist with tags
│   ├── sector_preferences.md # Preferred sectors
│   ├── alert_rules.md        # Custom alert conditions
│   └── analysis_notes.md     # Historical analysis notes
└── goals/
    ├── active/
    │   └── goal_20250527_001_aapl.json
    └── completed/
        └── goal_20250526_002_nvda.json

2.2 Memory Entry Format

---
title: "AAPL Technical Watch"
type: watchlist
created_at: 2026-05-27T10:00:00Z
modified_at: 2026-05-27T14:30:00Z
tags: [tech, swing-trade, ma-breakout]
---

## Entry Criteria
- Price above MA20
- Volume > 1.5x average
- RSI not overbought (>70)

## Exit Plan
- Stop loss: -8%
- Take profit: +15%

2.3 Core API

Method Description Priority
Memory.add(title, body, type, tags) Create new memory entry High
Memory.search(query, type, limit) Full-text search with ranking High
Memory.get(title) Retrieve specific entry Medium
Memory.update(title, body) Update existing entry Medium
Memory.delete(title) Remove entry Low
Memory.list(type) List all entries of type Medium

3. Research Goal System

3.1 Goal Lifecycle

created → active → [paused] → [completed | cancelled | failed]
                ↓
         evidence accumulation
                ↓
         criteria evaluation

3.2 Goal Structure

{
  "id": "goal_20250527_001_aapl",
  "symbol": "AAPL",
  "title": "Verify AAPL breakout above $195",
  "status": "active",
  "created_at": "2026-05-27T10:00:00Z",
  "modified_at": "2026-05-27T16:00:00Z",
  "criteria": [
    {"id": 1, "desc": "Price closes above $195", "weight": 0.4, "status": "pending"},
    {"id": 2, "desc": "Volume > 1.5x 20-day avg", "weight": 0.3, "status": "met"},
    {"id": 3, "desc": "RSI < 70 (not overbought)", "weight": 0.3, "status": "met"}
  ],
  "evidence": [
    {"date": "2026-05-27", "close": 193.5, "volume_ratio": 1.8, "rsi": 65}
  ],
  "current_analysis": "Price approaching resistance, volume building...",
  "next_check": "2026-05-28T09:30:00Z"
}

3.3 Goal API

Method Description Priority
Goal.create(symbol, title, criteria) Create new research goal High
Goal.add_evidence(goal_id, evidence) Add analysis evidence High
Goal.update_criteria(goal_id, criteria_id, status) Update criteria status High
Goal.get_active(symbol) Get active goals for symbol Medium
Goal.list(status) List goals by status Medium
Goal.complete(goal_id, summary) Mark goal as completed Medium
Goal.cancel(goal_id, reason) Cancel active goal Low

4. Integration Points

4.1 Pipeline Integration

  • Analysis results auto-added as evidence to active goals
  • Goal criteria auto-evaluated after each analysis
  • Memory watchlist drives default stock selection

4.2 CLI Commands

# Memory commands
python main.py --memory-add "AAPL Swing" --type watchlist --tags "tech,ma-breakout"
python main.py --memory-search "breakout"
python main.py --memory-list --type watchlist

# Goal commands
python main.py --goal-create AAPL --title "Verify breakout" --criteria "price>195,volume>1.5x"
python main.py --goal-list --status active
python main.py --goal-complete goal_20250527_001_aapl --summary "Breakout confirmed"

5. Implementation Notes

5.1 Key Design Decisions

Decision Rationale
File-based storage Zero dependencies, human-readable, git-friendly
YAML frontmatter Standard format, easy parsing, metadata separation
Auto-generated index O(1) lookup without external DB
Token-level search Supports CJK characters natively
Goal ID format goal_YYYYMMDD_NNN_symbol for easy sorting
